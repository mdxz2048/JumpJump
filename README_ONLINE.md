# SweetJumpJump 在线模式

## 启动网页 + 规则服务器

当前在线服务端已经改为 ASP.NET Core + WebSocket，服务端负责认证、房间和规则裁判，并直接托管 `Web/` 里的网页端。

```bash
dotnet run --project Server/SweetJumpJump.Server.csproj -- 53333
```

打开：

```bash
http://127.0.0.1:53333/
```

网页端默认内置两个棋手账号，密码暂时和账号相同：

```text
tian / tian
mdxz / mdxz
```

## 网页端进入游戏

1. 打开网页。
2. 输入棋手账号和密码进入。
3. 点「建房」，把 4 位房间号发给其他人。
4. 其他玩家输入房间号并点「加入」。
5. 点「开始本局」。

棋盘开始后，网页端只发送选子、移动、完成、放弃等意图；合法性、回合推进、AI 行动和最终状态都由后端规则核心裁定并广播。

大厅会显示可加入的发现房间列表。为避免误点或刷房，同一连接创建房间有 10 秒冷却，并且已经在未开始房间里时不能继续创建新房间。

只有创建房间的人会被标记为房主，只有房主可以点击「开始本局」。

在线对局里，网页端和 iPad 端都会把棋盘旋转到“自己的棋在下方”。棋盘各阵营角落会显示对应棋手昵称；AI 位置显示为「高级人机」。

## 成员管理

首页连续点击圆形标记 7 次，会显示管理员入口。管理员密钥暂时是：

```text
xiaozhi2048-admin
```

成员管理页可以查看当前在线成员、所在房间、座位、房主和管理员标记。
管理员也可以新增棋手账号和密码。当前账号数据保存在服务端内存里，服务重启后会恢复为默认内置账号。

## iPad 客户端兼容性

当前 iPad/Unity 客户端仍使用 `TcpClient` 连接旧版逐行 JSON 协议，并由客户端本地执行大部分规则；新版服务端是 `/ws` WebSocket 协议，并由服务端作为规则裁判广播 `STATE` 快照。因此当前 iPad 客户端与新版网页后端接口还不匹配，需要后续把 Unity 的 `OnlineClient` 和在线对局处理迁移到 WebSocket + `AUTH/CREATE/JOIN/START/STATE/SELECT/MOVE/FINISH/PASS` 这套协议。
